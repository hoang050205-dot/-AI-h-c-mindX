03. So Sánh Các Phương Án Kỹ Thuật (Trade-off Matrix)

Approach 1: Dedicated Assets + SQLite Pre-Indexed Engine + Modular CLI Tools
Khuyên dùng (Recommended)
Tạo mục assets/ riêng biệt chứa 4 tài sản gốc; Index Biểu thuế 2026 sang SQLite cục bộ; Trích xuất Phụ lục II sang UTF-8 text; Viết bộ CLI tools (query_hs_tariff, query_gri_rules, query_conditional_goods, generate_clearance_report) giúp Agent phản hồi dưới 1 giây mà không tốn RAM.
Ưu điểm (Pros)
  • Tra cứu siêu tốc (dưới 10ms thay vì 10s đọc file Excel 32MB)
  • Đáp ứng 100% yêu cầu 'tạo mục Assets riêng nằm trong skill không gộp chung'
  • Lập luận phân loại chặt chẽ nhờ toàn văn 6 Quy tắc GRI và Chú giải chi tiết
  • Có script tự động sinh Báo cáo tiêu chuẩn 4 phần gửi khách hàng
Nhược điểm (Cons)
  • Cần bước tiền xử lý index 1 lần ban đầu (đã thực hiện thành công)
Giả định chịu lực cốt lõi: File Excel Biểu thuế 2026 và các văn bản đính kèm là căn cứ chuẩn xác của Bộ Tài chính và Chính phủ.
Điểm gãy đầu tiên (First failure): Mặt hàng công nghệ quá mới xuất hiện chưa có tên trong danh mục AHTN hiện hành (cần áp dụng GRI 4).
Approach 2: Monolithic Dynamic Loading (Đọc file thô mỗi lần truy vấn)
Chậm & Tốn tài nguyên (Viable but Slow)
Mỗi khi người dùng hỏi, Agent mở file Excel 32MB bằng openpyxl và quét file PDF 604 trang bằng pypdf để tìm kiếm từ khóa.
Ưu điểm (Pros)
  • Không cần tạo cơ sở dữ liệu SQLite phụ trợ
  • Trực tiếp sử dụng file nguyên bản
Nhược điểm (Cons)
  • Mỗi câu hỏi mất từ 10 đến 25 giây để đọc file Excel 32MB
  • Tốn hàng trăm megabyte RAM, dễ bị timeout khi xử lý nhiều mặt hàng liên tiếp
  • Không tận dụng được tìm kiếm chỉ mục (Index Search)
Giả định chịu lực cốt lõi: Tài nguyên máy chủ hoặc máy người dùng đủ mạnh để load file 32MB liên tục.
Điểm gãy đầu tiên (First failure): Bộ nhớ bị phân mảnh hoặc CPU bị nghẽn khi người dùng tra cứu 10 mã HS liên tiếp.
Approach 3: External API / Cloud Dependent (Phụ thuộc Web Scraping)
Bất ổn & Phụ thuộc mạng (Overkill / Fragile)
Bỏ qua các file người dùng đưa, chỉ gọi search_web tra cứu biểu thuế trên các website thương mại bên ngoài (caselaw, customsthaiphong, thuvienphapluat...).
Ưu điểm (Pros)
  • Không cần lưu trữ file nặng trong workspace
Nhược điểm (Cons)
  • Bỏ phí 4 nguồn tài sản chính thống người dùng đã cất công cung cấp
  • Phụ thuộc mạng Internet, nguy cơ bị chặn IP bởi Cloudflare
  • Dữ liệu trên web thương mại có thể bị lỗi thời hoặc không đầy đủ biểu thuế FTA
Giả định chịu lực cốt lõi: Mọi mã HS và thuế suất đều tra cứu được ổn định trên internet công cộng.
Điểm gãy đầu tiên (First failure): Website tra cứu bên ngoài thay đổi cấu trúc HTML hoặc chặn bot khiến tra cứu thất bại.

Quyết Định Chọn: Approach 1: Dedicated Assets + SQLite Pre-Indexed Engine + Modular CLI Tools

Approach 1 là phương án hoàn hảo nhất: Vừa bảo toàn nguyên vẹn 4 nguồn tài sản quý giá do người dùng cung cấp trong thư mục 'assets/' riêng biệt của Skill, vừa giải quyết triệt để bài toán hiệu năng (đạt tốc độ phản hồi 5ms cho 19.895 dòng thuế), đồng thời cung cấp đầy đủ bộ công cụ phân loại 4 bước chuẩn hóa từ tính pháp lý, mã HS, thuế phí đến checklist hồ sơ hải quan.
